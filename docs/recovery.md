# Worker остановлен, доступ отозван: что произойдёт с экспортом

Инвариант: постановка экспорта в очередь не сохраняет право доступа навсегда.
Перед чтением документов worker повторно проверяет членство в организации,
а RLS ограничивает выборку её данными. Результат, аудит и удаление outbox
коммитятся вместе. Остановленный worker оставляет намерение в PostgreSQL.

## Повторить

Нужны Docker Compose, Python 3.12 и uv. Порт 8120 должен быть свободен:

```bash
export COMPOSE_PROJECT_NAME=proof-tenantdesk-demo
export BASE_URL=http://127.0.0.1:8120
uv sync --extra dev --frozen
docker compose up --build -d --wait --wait-timeout 180
make recovery
docker compose down -v
```

Это отдельный стенд: последняя команда удаляет его демонстрационные данные.
Recovery требует префикс `proof-` и управляет только worker указанного проекта.
До остановки worker он сверяет `BASE_URL` с опубликованным портом API этого
проекта. Чужой адрес или отсутствующий API приводят к отказу до любых изменений.

## Наблюдаемая граница отказа

Скрипт останавливает настоящий worker, создаёт две организации с разными
документами и приглашает viewer в первую. В очередь ставятся два экспорта:
от владельца и от viewer. Повтор ключа владельца возвращает то же задание;
оба задания остаются `queued`, пока worker остановлен.

Владелец отзывает членство viewer, затем worker запускается снова. Сценарий
ждёт завершения и проверяет:

- экспорт владельца стал `done` и содержит ровно его документ;
- экспорт viewer стал `rejected` с причиной `membership_revoked`;
- скачивание отозванным viewer возвращает 403;
- другая организация не может скачать экспорт первой: ответ 404.

Скрипт печатает JSON и возвращает worker в запущенное состояние даже при ошибке.
Он включён в CI: [recovery_smoke.py](../scripts/recovery_smoke.py).
Созданные демонстрационные аккаунты и задания остаются до удаления стенда.
Локальный результат этапа D: [verification-stage-d.json](verification-stage-d.json).
Проверка отказа при чужом адресе запускается после старта стенда:
`uv run pytest -q scripts/test_recovery_safety.py`.

## Для интервью и границы

Покажите промежуточное `queued`, отзыв членства и итоговый `rejected`.
Проверка membership находится внутри транзакции worker под блокировкой tenant;
сохранённая очередь не обходит актуальную авторизацию. RLS защищает от забытого
фильтра, но доверяет контексту backend и не защищает от захваченной роли БД.

Это проверка остановки процесса и последующего продолжения, а не физической
потери БД или высокой доступности. Два задания демонстрируют контракт, а не
пропускную способность worker.
